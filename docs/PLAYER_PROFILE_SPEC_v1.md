# 1. 這頁是什麼

「個人資訊」是登入會員在 Lobby 查看身份、帳號安全、VIP 與遊戲紀錄的入口。

使用者在這裡做六件事：

1. 查看頭像、暱稱、VIP、帳號、ID 與三種幣別餘額。
2. 查看與修改基本資料。
3. 綁定手機號碼或 Google。
4. 查看目前 VIP、等級權益、升級條件與保級狀態，並領取本級升級獎勵。
5. 查看 VIP機制說明中的等級總覽與規則說明。
6. 查詢最近 30 天內的 Mock 遊戲紀錄。

這個功能同時包含唯讀與可操作內容。基本資料、帳號綁定、頭像與 VIP 本級獎勵領取可以操作。VIP 等級仍由排程決定；遊戲紀錄只提供查詢。

# 2. 這頁不做什麼

| 不做的事 | 由誰負責 |
|---|---|
| 修改帳號或會員 ID | 帳號管理與客服流程 |
| 任意修改金幣、銀幣、銅幣餘額 | 金融模組。本頁只透過本級 VIP 獎勵領取增加對應幣別。 |
| 彙整歷史未領獎勵、跨級補領或真實獎勵入帳 | 後續獎勵帳本與後端規格 |
| 計算活躍指數或將其套用於 VIP 條件 | 新機制尚未定案，本版只保留顯示位置。 |
| 解除手機或 Google 綁定 | 後續帳號安全規格 |
| 綁定 Facebook、LINE 或 Apple | 本版不提供 |
| 更正已鎖定的生日或電子郵件 | 正式產品客服流程 |
| 手動升級、保級、降級或調整 VIP | VIP 排程與營運後台 |
| 顯示返水或連續降級資訊 | 本版 VIP 前台不提供 |
| 發送真實簡訊或連線 Google OAuth | 外部驗證服務 |
| 解鎖或設定頭像框 | 後續個人化功能 |
| 定義 API schema、enum、錯誤碼與資料庫 | 後端技術規格 |

| 本月升級保護 | 待結算月份曾完成升級時，該月不因保級不足而降級。 |
| 條件待設定 | VIP2 的升級儲值與投注尚未設定。畫面停止計算下一級進度。 |
| 活躍指數 | 新機制預留欄位。摘要固定顯示數字 0，無單位、不計算，也不代替保級活躍天數。 |
| VIP機制說明 | VIP 巢狀彈窗。包含「等級總覽」「規則說明」兩個文字頁籤。 |

例：會員目前為 VIP6、歷史最高為 VIP8。畫面必須以 VIP6 顯示目前權益、升級與保級條件。VIP8 只顯示於歷史最高欄位。

# 4. 畫面內容

個人資訊由五個區塊組成。

| 區塊 | 內容 |
|---|---|
| 1. 主彈窗標頭 | 英文眉標 `PLAYER PROFILE`、中文標題「個人資訊」、關閉按鈕。 |
| 2. 共用玩家摘要 | 頭像、暱稱、目前 VIP、帳號、ID、金幣、銀幣、銅幣。 |
| 3. 頁籤導覽 | 依序為「基本資料」「帳號綁定」「VIP 等級」「遊戲紀錄」。頁籤只顯示文字。 |
| 4. 頁籤內容 | 依目前頁籤顯示表單、狀態、VIP 資訊或遊戲紀錄。 |
| 5. 巢狀彈窗 | 頭像選擇、一次性資料確認、VIP機制說明。 |

## 4.1 入口與關閉

- 會員登入 Lobby 後，點擊 Header 的玩家頭像、暱稱或 VIP 資訊區，開啟個人資訊。
- 開啟時固定顯示「基本資料」。
- 關閉後再次開啟，仍固定回到「基本資料」。
- 主彈窗與巢狀彈窗都使用右上角關閉按鈕。
- 點擊背景遮罩不會關閉彈窗。
- 關閉巢狀彈窗只關閉該層，不關閉個人資訊主彈窗。

## 4.2 共用玩家摘要

共用玩家摘要在四個頁籤中持續顯示。更換頭像或修改暱稱後，摘要會同步更新。

## 4.3 基本資料

基本資料由七個欄位與一個儲存操作組成。生日或電子郵件首次保存非空值時，會先開啟一次性資料確認。

## 4.4 帳號綁定

帳號綁定包含手機號碼與 Google 兩張功能卡。每張卡分別顯示未綁定、處理中或已綁定狀態。

## 4.5 VIP 等級

VIP 等級包含四個主要資訊區塊。

| 區塊 | 內容 |
|---|---|
| 目前等級 | 目前 VIP、名稱、歷史最高、排程提示、歷史儲值、歷史投注、活躍指數與「VIP機制說明」入口。 |
| 等級權益 | 贈禮手續費、本級升級獎勵與領取按鈕。 |
| 升級條件 | 下一級、歷史儲值進度、本月有效投注進度、資料要求與剩餘差額。 |
| 保級狀態 | 本月儲值、本月投注、活躍天數、達標狀態與本月升級保護。 |

VIP機制說明包含兩個文字頁籤：

- 等級總覽：每次開啟時預設選中。顯示 VIP0～VIP15；欄位依序為等級、升級條件、保級條件、升級獎勵與贈禮手續費。目前等級特殊色標示，開啟或切回總覽時定位到該列。
- 規則說明：以升級、保級、降級與獎勵領取四段短文說明第 5.4.3、5.4.4 節規則。頁籤與關閉按鈕固定可操作，內容在彈窗內捲動。

等級權益不再顯示「已取得的等級獎勵不會因重新升級而重複發放。」提示。總覽上方不再顯示 AND 條件提示與「贈禮手續費：現行費率 5%」徽章；原本判定規則與表格費率數值不變。

## 4.6 遊戲紀錄

遊戲紀錄包含日期查詢、查詢前提示、查無資料提示、結果表格與分頁控制。

### 5.4.3 VIP 判定規則

- 每日 00:00 判斷升級。
- 升級必須同時達成所有已設定條件。
- 同時符合多個等級時，升到最高符合等級。
- 先判斷升級。若本次未升級，才於月度結算判斷保級。
- 保級開啟時，必須同時達成所有已啟用條件。
- 保級關閉時，會員無條件保級。
- 未升級且未保級時，下降 1 級。
- 本月曾完成升級時，該月不會因保級不足而降級。
- 同一等級的升級獎勵只發放一次。重新升回同一等級不會重複發放。
- 前台不顯示連續降級次數。
- 前台不顯示返水。

### 5.4.4 本級升級獎勵領取

- 只處理會員目前生效等級的獎勵，不提供歷史未領清單或跨級補領。
- 點擊「可領取」後，依第 5.4.2 節將獎勵加入對應幣別錢包，同步更新共用玩家摘要與 Header 餘額。
- 成功後顯示包含等級、幣別與數量的 Toast，並產生一筆免費獎勵金融 Mock 紀錄，來源為「VIP {等級} 升級獎勵」。
- 按鈕直接由「可領取」改為反灰且停用的「已領取」，不顯示「領取中」等第三種狀態。
- 領取前驗證目前等級、獎勵配置與已領取等級集合；連續點擊只能增加一次餘額與一筆紀錄。
- 領取紀錄保存在共用金融 Mock 狀態，切換頁籤或關閉再開啟不清除；重新整理後與錢包一起回到初始狀態，不寫入身份保存資料。
- VIP0 沒有獎勵，不得產生任何入帳或紀錄。
- 不新增真實 VIP 排程或後端獎勵帳本。

# 7. 查詢、排序與分頁

本章只適用於「遊戲紀錄」。其他頁籤沒有查詢、排序或分頁。

## 7.1 查詢條件

| 欄位 | 型態 | 說明 |
|---|---|---|
| 開始日期 | 日期 | 最早為今天往前 30 天。最晚為今天。 |
| 結束日期 | 日期 | 最早為今天往前 30 天。最晚為今天。 |

規則：

- 日期區間包含開始日與結束日。
- 開始日期不可晚於結束日期。
- 修改日期不會立即查詢。使用者必須按「查詢」。
- 每次查詢完成後回到第 1 頁。
- 本版沒有重置按鈕。

## 7.2 排序

- 本版沒有可操作的排序欄位。
- Mock 紀錄建立後依時間由新到舊排列。
- 時間只用於篩選。結果表格不顯示時間。

## 7.3 分頁

- 每頁 10 筆。
- 顯示上一頁、目前頁／總頁數與下一頁。
- 第 1 頁停用上一頁。
- 最後一頁停用下一頁。

## 14.8 保存邊界

- 暱稱、帳號、登入方式、頭像、ID、生日、電子郵件、手機、簡介與手機／Google 綁定隨登入身份保存。

- 錢包、金融紀錄、VIP 指標、VIP 已領取等級集合與遊戲紀錄不寫入身份保存資料。
- VIP 領取後在同一 Mock 登入期間保持已領取；重新整理後，領取集合與領取紀錄清除，錢包重置。重新登入建立新的 Mock 使用者。
- 一般會員 Mock 使用 VIP6。訪客 Mock 使用 VIP0。
- 一般會員 Mock 的 VIP 指標為歷史儲值 48,600、歷史投注 8,920,000、本月儲值 21,500、本月投注 428,000、活躍 18 天，並啟用本月升級保護。
- 訪客的上述 VIP 指標皆為 0，且不啟用本月升級保護。
- 摘要活躍指數在兩種登入類型皆固定顯示 0；上述活躍 18 天只供既有保級進度使用。
- 一般會員 VIP6 的本級獎勵初始可領取；訪客 VIP0 無獎勵。
