## 依據與適用方式

上游為 [PRD 原始規範](PRD.md)，原文完整保留，不納入 HTML 閱讀版。此文件記錄使用者確認的 APP 適用方式；原規範提及的 GAME_LIST_PRD_SAMPLE.md 尚未取得，不宣稱已核對範例。

- 總綱新增第 00 章產品簡述，保留 01～15 章編號與功能架構，第 00 章正文直接保留總綱內，並提供導覽、關係與全書變更摘要。
- 第 00 章是總綱內的產品介紹，不另分冊；第 01、02 章採基礎文件結構，沿用六列控制表、表格寫法、責任範圍、待確認、版本及交付檢查；不強套功能的 17 節。
- 第 03～12 章採固定 17 節。不適用保留節次及理由。多個子功能依各節分組，不混用狀態與欄位。
- 第 13～15 章獨立保存跨介面流程、驗收證據與完整玩家旅程；功能內三視角故事引用同一條規則，不取代跨功能旅程。
- 共用名詞由第 02 章維護；功能只保留必要摘要與連結。已確認規則、原型現況與未決事項分開。
- 狀態代碼只列已查證的原型對照，不等同正式 API。帶入參數使用資料語意；無帶入內容寫「無」。
- 五種頁面狀態逐項檢查；未定義不可寫成不適用或自行新增重試、權限流程。
- 每章故事數依規則覆蓋決定，不以湊滿 8～12 則新增需求。GIVEN 具體、THEN 可觀察，每則只處理一個重點。
- 現有 FLOW／US／SC／AC 不改號。新故事用 US-U-章號-流水號、US-D-章號-流水號、US-Q-章號-流水號；新問題用 Q-章號-流水號。
- 驗收表採 ID、主題、驗收敘述三欄，消除上游「四欄」文字與三欄骨架的落差。既有 AC 如需拆細，新項接續最大號，保留舊編號與關係。
- 每份文件保留自己的沿革；總綱只寫跨文件改版摘要。待確認決議後保留原編號與問題。
- Markdown 是來源，HTML 逐份生成。文件交付檢查與產品操作驗收分開。
