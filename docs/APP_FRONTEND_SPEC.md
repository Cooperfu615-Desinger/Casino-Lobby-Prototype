## 使用與撰寫方式

後續開立工作單時，引用功能章節及適用的 FLOW／US／SC／AC，寫明目前行為、調整目標、影響畫面與驗收條件。完成調整後同步規格正文及變更紀錄，讓文件維持最新狀態。

- 依功能填寫正文，區分已確認需求、原型現況／限制與待確認事項。
- 第 03～12 章使用[功能章節模板](spec-templates/FEATURE_TEMPLATE.md)；章內有多個子功能時各自套用，保留同一章入口。
- 第 15 章使用[玩家故事模板](spec-templates/PLAYER_STORY_TEMPLATE.md)。情境以玩家目標及必要狀態組合為單位，不推測尚未確認的服務能力。
- 第 13 章描述跨介面交接；第 15 章描述「某種狀態的玩家如何完成目標」；第 14 章集中追蹤驗收覆蓋與執行證據。
- 現有來源：[個人資訊規格](PLAYER_PROFILE_SPEC_v1.md)、[銀行優惠碼規格](PROMO_CODE_SPEC.md)、[美術清單](art-design-checklist.md)。細節合併時逐項核對版本與決策，不直接整份複製。
- Markdown 為正文來源；HTML 閱讀版由 `python3 scripts/export_spec_html.py` 同步產生。尚未製作 Word／PDF。

| 底部獎勵卡 | 個人資訊的獎勵卡頁籤 | 直接選中獎勵卡頁籤 | 關閉後回大廳 |
| 底部聊天／客服 | 聊天與客服 | 分別開私人聊天／客服 | 關閉整個介面回大廳 |
| 底部每日任務／活動 | 任務與活動 | 分別開每日任務／活動 | 關閉整個介面回大廳 |
| 底部銀行 | 銀行 | 儲值 | 關閉回大廳 |

| 底部保險箱 | 保險箱 | 保險箱頁籤、預設存入模式 | 關閉回大廳 |
| 底部信箱 | 信箱 | 營運公告，預設選擇首筆符合分類的信件 | 關閉回大廳 |

### 02.3 身份與頁面層級名詞

| 統一名稱 | 意義與邊界 |
|---|---|
| 未登入 | 目前沒有登入身份，主內容顯示登入頁。 |
| 訪客 | 以訪客登入建立的 Mock 身份，可進大廳；目前為 VIP0、無個人邀請碼、不可兌換優惠碼，也不顯示自動傳送設定入口。其他功能限制須逐項描述，不能概括成訪客只能瀏覽。 |

## 05. 遊戲進入與離開

**狀態：**第 3 批初稿，依目前遊戲卡、幣別選擇、遊戲室與返回流程整理。原型遊戲畫面為示意，不代表已串接遊戲供應商或正式結算。

### 05.1 功能目的與範圍

玩家從大廳選擇遊戲，確認可用幣別後進入，並能離開返回大廳。活動銀幣使用與轉換銜接第 07 章；大廳分類與收藏的完整操作於第 04 章補寫。

進入不先扣一筆入場費，也不把錢包搬移至另一個遊戲帳戶。不同遊戲目前共用示意遊戲畫面，顯示所選遊戲的名稱、供應商與幣別；未提供實際下注、輸贏結算或逐局紀錄。

### 05.2 入口、預設畫面與返回

| 入口／操作 | 帶入與預設 | 返回／交接 |
|---|---|---|
| 點大廳遊戲卡 | 開該遊戲啟動視窗，帶入遊戲及目前大廳幣別篩選 | 右上關閉或點背景取消，留原大廳及篩選 |
| 大廳未指定幣別（全部） | 初選遊戲第一種支援幣別；若不可用，改選清單中第一個可用幣別 | 全部不可用時進入按鈕停用 |
| 大廳指定幣別且遊戲支援 | 保留該幣別為選中，即使餘額不足也不自動換成別種 | 玩家可手動改選其他可用幣別；原選項不可用時不能進入 |
| 確認進入 | 保存這次遊戲及選中幣別，先顯示品牌載入，再顯示遊戲室 | 載入畫面尚無獨立取消或失敗重試入口 |
| 遊戲室離開 | 直接結束本次原型遊戲畫面，不另彈離開確認 | 回大廳；不自動停用卡、不額外轉換或退款 |
| 轉換結果「查看紀錄」 | 標記結果已讀、離開遊戲並開銀行紀錄 | 金融紀錄篩選規則見 08.4.4 |

點遊戲卡時就寫入本機最近點選紀錄，因此取消啟動也已留下點選資料；目前沒有供玩家瀏覽的最近遊玩清單。遊戲室與大廳互相切換時大廳會重建，分類／供應商／幣別篩選及側欄開啟狀態回初始值，收藏偏好仍保存；不要把取消啟動與離開遊戲的返回結果混為一談。

### 05.3 畫面區塊與內容

| 區塊 | 內容 |
|---|---|
| 啟動視窗標頭 | 遊戲名稱、圖示、供應商及 RTP 展示值；RTP 不作本文件的數學保證 |
| 幣別選擇 | 金幣、銀幣、活動銀幣、銅幣四選項，各列餘額、選中狀態及可用／不支援提示 |
| 可用數量 | 分別顯示可用選項數及遊戲支援種類數，兩者可能不同 |
| 啟動操作 | 進入遊戲按鈕；選項不可用時停用 |
| 遊戲室標頭 | 遊戲名稱與供應商、選定幣別及餘額、離開按鈕 |
| 遊戲內容 | 示意圖；活動銀幣模式另顯示卡片名稱與「模擬完成流水」 |

### 05.4 欄位與顯示規則

幣別可選必須同時符合「遊戲支援」與「該錢包可用額度大於 0」。金銀銅使用一般錢包，活動銀幣使用有效且使用中的卡片餘額；保險箱、未啟用卡片總額及活動金不納入可用選項。

| 狀態 | 顯示與操作 |
|---|---|
| 遊戲不支援 | 選項停用，說明此遊戲不支援此幣別；不是餘額不足 |
| 支援但一般錢包為 0 | 選項停用，提示目前不可用／餘額不足 |
| 支援但無可用活動銀 | 選項停用，提示需先啟用銀幣獎勵卡；已過期卡不構成可用卡 |
| 選定幣別有效 | 可按進入；入場後保留該幣別，遊戲室無切換錢包入口 |
| 活動銀卡已完成或失效 | 遊戲室卡片區顯示「本次獎勵卡已完成或失效」，Mock 流水按鈕停用，不自動退回大廳 |

### 05.5 操作與使用流程

1. 在大廳選遊戲，於啟動視窗確認帶入幣別及可用額度。
2. 若目前不可用，可改選其他可用幣別；或取消，回銀行取得一般錢包餘額／至獎勵卡啟用卡片後再進入。沒有自動跳儲值的額外步驟。
3. 按進入，等待載入，核對遊戲室名稱及幣別。此時一般錢包與卡片不因入場而扣減。
4. 活動銀模式可使用 Mock 完成流水，轉換計算與卡片更新完整引用 07.5.4；其他幣別不顯示這項操作。
5. 按離開直接回大廳；若在轉換結果選查看紀錄，則改開銀行紀錄。單純確認／關閉結果留在遊戲室。

### 05.6 狀態、限制與例外

載入為原型展示，尚無逾時、供應商維護、斷線重連、進出遊戲帳務交接或正式失敗畫面。遊戲期間重新整理不恢復本次遊戲，保留的身份使玩家回到大廳；金融及卡片狀態依 02.7 重置。已取得的帳號、好友或卡片資料並不因此證明正式遊戲有持久化能力。

入場時只帶遊戲與幣別，活動銀卡由當下有效使用中卡取得；原型未固定一個正式的遊戲局與卡片結算關係。跨到期時刻及遊戲外狀態變動仍需獨立驗證，不以一般成功流程取代。

## 06. 個人資訊與會員功能

**本章範圍：**自己的玩家摘要、邀請碼、基本資料、帳號綁定、頭像、VIP 權益與領獎，以及遊戲紀錄。獎勵卡管理統一引用[第 07 章](#ch-07)；查看其他玩家的資訊卡屬第 11 章。

**狀態：**第 2 批初稿。本章以既有[個人資訊規格](PLAYER_PROFILE_SPEC_v1.md)及現行操作邏輯核對整理；驗收條件已撰寫，本批未執行瀏覽器或正式服務驗收。

### 06.1 功能目的與範圍

玩家在同一個「個人資訊」視窗查看身份、完善資料、確認綁定、理解 VIP 權益並查詢遊戲紀錄。美術、前後端與測試可依本章的小節及驗收編號建立調整工作單；單純編修文件不改變既有功能規則。

個人資訊有五個頁籤，依序為「基本資料」「帳號綁定」「VIP 等級」「獎勵卡」「遊戲紀錄」。一般會員與訪客均可開啟；未登入時不顯示。訪客綁定手機或 Google 不會自行改變身份，也不因綁定而取得邀請碼。

### 06.2 入口、預設畫面與返回

| 入口／操作 | 預設內容或帶入資料 | 返回／保留方式 |

主視窗不以背景點擊關閉，亦未提供全域 ESC 關閉規則。未送出表單時切頁／關閉不另跳出捨棄確認；重開依已保存資料初始化。儲存、驗證中的離頁不等於取消已送出的操作，原型尚未提供這些延遲操作的取消流程。

#### 06.4.1 身份、邀請碼與基本資料

| 欄位 | 可編輯／必填 | 格式及限制 | 初始／保存後呈現 |
|---|---|---|---|

複製邀請碼只複製畫面上的 8 碼；成功顯示「邀請碼已複製」，失敗顯示「複製失敗，請長按或選取邀請碼複製」。文字可手動選取；複製不建立推薦關係，也不發放獎勵。三種碼的用途引用 02.5。

#### 07.5.2 合併資格與流程

1. 至少有兩張合格卡，合併入口才可操作。合格卡須為未啟用或已停用，且每張距離實際到期時間**超過 72 小時**。
2. 張數至少兩張、無上限；使用中卡須先退出合併模式並停用，再進入選取。剩餘時間小於或等於 72 小時，包括恰好 72 小時，均不可合併；這個限制不阻擋未過期卡片啟用。
3. 進合併模式後勾選卡片。選取未滿兩張或任何選中卡已不符資格時，不顯示有效結果預覽，確認合併停用。
4. 預覽列出張數、目前餘額、起始餘額紀錄、轉換上限、流水及最早到期日。確認前不扣卡、不改錢包。
5. 確認時再次檢查每張卡的狀態與期限，一次將來源卡標為已合併並建立新卡。新卡為未啟用，置於最上方，回到列表頂部並提示「已建立活動銀幣合併卡，請啟用後使用」。
6. 若確認時資格已變，原卡不變，清除選取並提示「卡片狀態或剩餘期限已變更，請重新選取」。玩家可重選或取消。
7. 取消只退出模式、清除選取；合併完成後沒有拆回原卡的操作。來源卡不能再次獨立使用，合併卡符合資格時可與其他卡再合併。

| 轉換上限 | 所選卡片上限直接加總 |
| 有效期限 | 所選卡片中最早的到期日；不展延短期限卡 |
| 來源張數 | 累計原始來源張數；合併卡再參與時須包含先前來源 |

五項原始數值各自直接加總，**不依流水倍數重新換算**。合併後的流水與起始餘額比例可能與單一卡片不同，這是直接加總的結果。合併本身不改一般金銀銅、不增加付費儲值、不產生銀幣入帳或銀行轉換紀錄。

以下為計算驗收用資料，假設兩卡均未啟用、都距到期超過 72 小時：

| 項目 | 卡 A | 卡 B | 合併結果 |
|---|---|---|---|
| 起始餘額紀錄 | 10,000 | 5,000 | 15,000 |
| 目前餘額 | 8,000 | 4,000 | 12,000 |
| 已達成流水 | 20,000 | 30,000 | 50,000 |
| 目標流水 | 100,000 | 100,000 | 200,000 |
| 轉換上限 | 10,000 | 10,000 | 20,000 |
| 到期 | 2026/12/31 | 2026/12/20 | 2026/12/20 |
| 狀態 | 未啟用 | 已停用 | 未啟用，顯示由 2 張合併 |

此例目前餘額為 12,000，而起始紀錄為 15,000，兩者都須保留；進度為 50,000 ÷ 200,000＝25%。具非零流水或變動餘額的測試卡需另行準備，原型目前沒有逐局累積介面可自然建立這組資料。

#### 07.5.4 遊戲使用與流水轉換

玩家先啟用卡，再於支援活動銀幣且有可用餘額的遊戲選擇活動銀幣進入。未啟用時即使總額為正，仍不能以活動銀幣進入；遊戲不支援該幣別時也不可選。

原型遊戲室提供 Mock 完成流水操作，會一次將已達成流水補到目標並執行轉換；它不是逐局下注、流水累積或正式結算的證據。

- 轉換額度＝目前餘額與轉換上限的較小值；系統回收＝目前餘額減轉換額度。原型以非負整數計算，有小數先無條件捨去；不把此數值處理自動當成正式帳務精度決策。
- 只接受有效、使用中的卡片，且轉換額度須大於 0。不能轉換未啟用、已停用、過期、已合併或已轉換卡。
- 成功時卡片變已轉換、目前餘額歸零、保留轉換／回收／時間；一般銀幣增加轉換額度，新增一筆「獎勵卡流水完成・卡片名稱」紀錄。
- 顯示轉換結果視窗：轉換前額度、轉入銀幣、系統回收與銀幣錢包結果。確認／關閉只標記已讀並留在原畫面；「查看紀錄」結束遊戲並進銀行紀錄。
- 同一卡片不能重複入帳。查看或關閉結果不再次發獎；合併來源也不能另行轉換。

例如目前餘額 12,000、上限 10,000，轉入銀幣 10,000、回收 2,000；餘額 5,000、上限 10,000，則轉入 5,000、回收 0。這兩例用來說明公式，非新增發獎配置。

## 08. 銀行、儲值與優惠碼

**狀態：**第 3 批初稿，優惠碼沿用既有[銀行優惠碼確認版](PROMO_CODE_SPEC.md)，儲值及紀錄依現行入口與資料更新整理。付款是 Mock，不會呼叫商店收款。

### 08.1 功能目的與範圍

銀行提供「儲值」「優惠」「紀錄」三頁籤。玩家可選購金幣方案、輸入優惠碼確認領取，以及檢視金融操作紀錄。大廳促銷購買也使用同一支付視窗，但促銷購買與銀行優惠碼不是同一流程；保險箱與金銀幣兌換另見第 09 章。

## 09. 保險箱、贈禮與兌換

**狀態：**第 3 批初稿，依目前資產表單及共用餘額更新整理。贈禮只模擬送方扣款與紀錄，對方實收是預覽／提示，尚未向真實接收者入帳。

### 09.1 功能目的與範圍

保險箱包含「保險箱」「贈禮／轉點」「兌換」三頁籤。玩家可以在錢包與保險箱間移動金幣、以保險箱金幣贈禮，或交換一般金銀幣。活動金、活動銀、獎勵卡及銅幣不參與本章操作。

保險箱不是另一種幣別；存取是同一身份的金幣位置改變，贈禮與金銀幣兌換則有不同的來源、計算與結果，不共用一套扣款說明。

### 09.2 入口、預設畫面與返回

| 入口／操作 | 預設及帶入 | 完成／返回 |
|---|---|---|
| 底部保險箱 | 保險箱頁、存入模式，金額空白 | 主關閉回大廳 |
| 玩家資訊卡贈禮 | 先關玩家卡，帶接收者 ID 進贈禮頁 | 完成留贈禮頁；主關閉回大廳，不自動回玩家卡 |
| 同一視窗切頁籤 | 保留本視窗各表單狀態 | 主關閉再開重建表單與預設模式 |
| 存入／取出切換 | 換來源餘額，清空該金額 | 留保險箱頁 |
| 兌換方向切換 | 換一般金／銀來源，清空兌換金額 | 留兌換頁 |
| 送出有效操作 | 顯示共用處理中遮罩後執行 Mock | 成功留原頁並清空本次輸入；失敗保留輸入及提示 |

主關閉不支援背景點擊。存取、贈禮、兌換都在表單確認按鈕直接送出，沒有第二個確認彈窗。未送出時可切頁、改模式或主關閉；處理中沒有另設取消操作。

### 09.4 欄位與計算規則

#### 09.4.1 共用金額輸入

金額欄只留下數字，並截到當前來源餘額上限；空字串表示未輸入。原型是移除非數字字元而非解析小數，例如輸入 `1.5` 會成 `15`，不能把小數輸入當作可接受的金額格式。介面只供非負整數使用，零不能提交。

保險箱提供滑桿與快捷比例，按比例向下取整；MAX 為全額來源。贈禮金額最多為目前保險箱金幣，沒有快捷比例。兌換快捷比例另依銀換金單位調整，見 09.4.4。

#### 09.4.2 存入與取出

| 操作 | 來源／目的地 | 成功計算與紀錄 |
|---|---|---|
| 存入 X 金幣 | 一般錢包 → 保險箱 | 錢包金減 X、保險箱金加 X；一筆「錢包存入保險箱」紀錄 |
| 取出 X 金幣 | 保險箱 → 一般錢包 | 保險箱金減 X、錢包金加 X；一筆「保險箱取出至錢包」紀錄 |

金額需大於 0 且不超過來源，無手續費。表單「操作後可用」指來源餘額減本次金額，不是目的地餘額。成功清空金額；來源不足時顯示錢包金幣不足／保險箱餘額不足，沒有成功紀錄。

#### 09.4.3 玩家贈禮

接收者 ID 可由玩家卡帶入，也可手動輸入；去除前後空白後非空即可送出。原型未檢查接收者是否存在、是否自己、是否被封鎖或是否具接收資格，不能以成功提示證明已送達。

| 項目 | 計算／現況 |
|---|---|
| 送方扣除 | 等於輸入 X 金幣，從保險箱扣除，錢包金幣不直接扣 |
| 手續費 | X × 5%，向下取整 |
| 對方實收預覽 | X − 手續費，最低 0；費用包含在送方輸入內，不另加扣 5% |
| 成功紀錄 | 贈禮類別一筆，來源「贈送給 {接收者 ID}」，金額為送方扣除 X |
| 今日剩餘／單次上限 | 畫面固定顯示 5／10 次及 1,000,000 點；未隨操作遞減，也未依此上限拒絕提交 |
| VIP | 顯示目前等級，但此表單固定使用 5% 計算，尚未按級別動態取費率 |

例如送出 1,001 金幣，手續費為 50、對方實收預覽 951，送方保險箱只扣 1,001。銀行紀錄未另外拆列費用／對方入帳，對方錢包沒有實際更新。正式接收者驗證、次數／限額及收方帳務如需補齊，應在調整工作單明列，不當作現有能力。

成功後清空接收者與金額，留贈禮頁；餘額不足時提示先存入金幣。一般會員與訪客進此表單目前沒有獨立的身份限制，不自加 VIP 門檻。

#### 09.4.4 一般金銀幣兌換

| 方向 | 可送出金額 | 結果 |
|---|---|---|
| 金 → 銀 | 正整數、不超過一般金幣餘額 | 扣 X 金、加 X × 100 銀 |
| 銀 → 金 | 正整數且為 100 的倍數、不超過一般銀幣餘額 | 扣 X 銀、加 X ÷ 100 金 |

兩方向均無手續費。銀換金若輸入非 100 倍數，摘要可能顯示向下取整的預覽，但確認按鈕仍停用，不應把預覽視為已允許尾數丟棄。快捷 25%／50%／75%／MAX 在銀換金時再向下取到 100 倍數，例如餘額 1,050、MAX 帶 1,000，完成後留 50 銀幣。

成功清空金額、金銀餘額同步，新增一筆來源幣別與目的幣別的兌換紀錄。兌換不算付費儲值，不影響 VIP 指標、銅幣、活動額度、卡片或保險箱。

## 10. 每日任務、活動與排行榜

**狀態：**第 3 批初稿。簽到與領卡、活動報名及榜單以現行原型為依據；活動日期、獎勵與名次為示範資料，不作正式發獎或即時排行承諾。

### 10.4 欄位與顯示規則

#### 10.4.1 簽到、補簽與節點

日曆以瀏覽器本地日期及當月天數建立，沒有切換其他月份的入口。今天未簽可操作，已簽與未來日期停用，僅本月今天之前的漏簽日可補。每日任務按鈕與今天日期格都能完成當日簽到。

| 項目 | 本版規則 |
|---|---|
| 今日簽到 | 增加一日累積進度、日期改已簽，不扣幣、不直接發一般錢包或卡片 |
| 補簽 | 每個漏簽日支付 100 一般銀幣，成功補一日進度；活動銀、保險箱或其他幣別不能代付 |
| 進度初值 | 原型預設累積 20 天，與日曆初始已簽日數獨立；每新增簽／補一日，累積加一 |
| 獎勵節點 | 第 10、15、20 天手動領活動銀卡；金額、流水及期限引用 07.4 |
| 無額度節點 | 第 5、7、25、30 天只標記里程碑完成，不增加餘額或卡片；前兩項原型初始已完成 |
| 領取資格 | 已達節點且未領才可操作；未達停用，成功後已領停用；刪卡／合併不恢復資格 |

補簽不足 100 銀幣時顯示「銀幣不足，無法補簽」，確認層仍在，日期與餘額不變；可取消後取得銀幣再返回。成功顯示扣款提示並關閉確認層。補簽目前只改銀幣與任務進度，沒有新增銀行金融紀錄。

#### 10.4.2 活動與報名

進行中分類同時包含「進行中」及「即將結束」的活動。分類與可報名狀態依示範資料的狀態欄位決定，未根據畫面日期自動切換；原型日期文字與真實今天不一致時，不應推論正式活動仍有效。

| 活動狀態 | 按鈕及結果 |
|---|---|
| 進行中／即將結束、未報名 | 可按「立即參與」，成功提示完成 Mock 報名，卡片與詳情更新已報名 |
| 已報名 | 顯示「已完成 Mock 報名」且停用；沒有取消報名入口 |
| 即將開始 | 「尚未開始」停用，可閱讀詳情 |
| 已結束 | 「活動已結束」停用，可閱讀介紹與固定示範獲獎名單 |

報名只保存活動識別，不扣費、不自動發獎、不驗證 VIP／儲值／遊戲參與條件，也不開啟遊戲。活動介紹中的營運條件若要正式執行，應由後續工作單補檢核與結果，不因文案存在宣稱已完成。

#### 10.4.3 排行榜

倍數榜以倍數、贏分榜以分數、富豪榜以金幣展示數值；不將三者合算。每榜固定前 10 名，不提供分頁、個人排名查詢或點玩家開資訊卡。顯示「幾秒／分鐘前更新」的數字隨停留時間增加，但列表是靜態 Mock，不會因此重新取得成績；本機操作不改名次，也不發排名獎勵。

### 10.5 操作與使用流程

| 流程 | 玩家操作 | 完成結果 |
|---|---|---|
| 當日簽到 | 每日任務 → 今日簽到／今日日期格 | 日期已簽、累積加一，留任務頁；達到節點後仍需手動領取 |
| 補簽 | 選漏簽日 → 檢查 100 銀幣費用 → 確認 | 扣銀幣、補進度、關子層；取消不扣；不足保留錯誤與確認層 |
| 領里程碑 | 點已達未領節點 | 卡片節點新增未啟用卡；無額度節點只標記完成 |
| 使用獎勵 | 領卡後從底部獎勵卡前往查看 | 不自動跳頁；啟用及遊戲使用接第 07、05 章 |

| 查看榜單 | 排行榜 → 倍數／贏分／富豪 | 換同一排行介面的展示內容，不改資產 |

### 10.6 狀態、限制與例外

已簽、已領、已報名按鈕會停用，獎勵卡另有同步資格檢查，避免同一節點重複發卡。簽到／補簽／報名本身仍是前台共用狀態，快速重複提交及跨裝置併發未提供正式交易保證，不能只憑停用樣式當作後端防重複完成。

本月日曆與累積值為展示資料，未實作月份切換排程、跨午夜自動重建、正式累積／重置週期、活動空資料或服務失敗頁。記憶體中的進度與報名在關閉功能後保留，刷新重置，也未依登入帳號完整隔離。

**玩家目標：**身為已登入玩家，我想確認想玩的遊戲能使用哪種餘額，選定後進入，離開時回到大廳。

**初始狀態：**在大廳、有至少一個一般錢包正餘額；依情境另備全部餘額為零、活動銀卡未啟用或已啟用。尚未進遊戲；遊戲識別與支援幣別需從實際列表選取。本批完成進出情境，分類／收藏尋找的完整步驟待第 04 章。

| 2 | 核對各幣別可用餘額，選可用項 | 選中與可用狀態分開；不合條件可改選或取消 |
| 3 | 確認進入並等待載入 | 遊戲室顯示同一遊戲、供應商及幣別；入場不扣額 |
| 4 | 按離開 | 回大廳，收藏保留，原篩選重建；不新增結算紀錄 |
