## 1. 這個功能是什麼

銀行提供「儲值」「優惠」「紀錄」三頁籤。玩家可選購金幣方案、輸入優惠碼確認領取，以及檢視金融操作紀錄。大廳促銷購買也使用同一支付視窗，但促銷購買與銀行優惠碼不是同一流程；保險箱與金銀幣兌換另見第 09 章。

<a id="section-02"></a>

## 2. 這個功能不做什麼

| 不做的事 | 負責位置 |
|---|---|
| 保險箱存取、贈禮及金銀兌換 | 第 09 章資產操作 |
| 卡片啟用與轉換 | 第 07 章獎勵卡 |
| 真實收款、收據、退款及優惠碼產碼 | 後續支付服務及營運後台規格 |

## 3. 名詞說明

| 名詞 | 定義與例子 |
|---|---|
| 金幣／售價 | 金幣是遊戲資產；畫面 $ 售價尚未指明正式計價幣別。 |
| BONUS／入帳數 | 500,000 金幣、+10% 文案的方案只入帳 500,000，不再加一次。 |
| 促銷購買／優惠碼領取 | 前者使用支付視窗，後者預覽後直接領取，沒有付款步驟。 |
| 付款狀態／紀錄狀態 | 付款處理中不會先建立處理中金融紀錄；歷史種子狀態不能推導可重試。 |
| 玩家帳號／會員 ID | 支付畫面標為玩家帳號，實際顯示會員 ID；不當作登入帳號。 |

## 5. 欄位說明

#### 08.4.1 儲值方案與促銷

下表為目前原型方案，售價保留畫面 `$` 文字，未指定正式計價幣別；不推定稅額或匯率。

| 入帳金幣 | 畫面售價 | BONUS 文案 |
|---|---|---|
| 100,000 | $4.99 | 無 |
| 500,000 | $19.99 | +10% |
| 1,200,000 | $49.99 | +20% |
| 3,000,000 | $99.99 | +50%，最佳方案 |
| 7,500,000 | $199.99 | +80% |
| 20,000,000 | $499.99 | +100% |

**入帳以方案列出的金幣數為準，BONUS 不再加算一次。** 例如 500,000、+10% 方案目前入帳仍為 500,000；文案是否表示已含加碼，原型沒有另行定義，後續調整時應同時對齊方案及確認畫面。

促銷目前呈現「新春紅包禮」「週末狂歡包」「首充雙倍送」「月卡尊享」四項。SALE 由第一項開啟，其他大廳促銷圖示可帶入不同起始項；左右切換不循環，首末相應按鈕停用。原資料中的 VIP 專屬及幸運轉盤方案目前不在此輪播。

促銷的首充、週末、期限與每日自動領取文案仍為示範；購買沒有另外檢查首次儲值／星期／到期，也沒有月卡每日派發。確認付款只按該方案金幣一次入帳；不由文案推算第二份獎勵。

#### 08.4.2 付款欄位與結果

| 項目 | 規則 |
|---|---|
| 方案 | 銀行方案顯示金幣方案；促銷帶入自身名稱；金幣數與售價不讓玩家編輯 |
| 玩家識別 | 畫面欄名為「玩家帳號」，目前實際顯示會員 ID；不應把它當登入帳號 |
| 通路 | App Store 預設，可單選 Google Play；僅確認階段可切換 |
| 處理中 | 點確認付款後進處理中，關閉停用，確認表單不再顯示 |
| 成功 | 一般金幣增加方案值、一筆成功儲值紀錄、餘額動畫及 Toast；按完成才退出 |
| 失敗 | Mock 入帳條件不成立時回確認，提示「目前無法完成儲值，請重新登入後再試」；不顯示成功 |

原型只要求有登入身份及正的金幣數，未另設訪客不可儲值的限制。儲值成功目前不更新 VIP 歷史／本月儲值指標，也沒有真實訂單、收據驗證、取消付款回呼、退款或支付防重複憑證。正常一次操作應只產生一筆入帳；重開購買是新的 Mock 操作，不代表同一正式訂單可重複付款。

#### 08.4.3 優惠碼格式、資格與獎勵去向

優惠碼固定 8 碼英數字，忽略前後空白及大小寫；中間空白、其他字元或錯誤長度不接受。欄位輸入轉大寫，未限制只能先輸入 8 碼；非空時可送出檢核。訪客可瀏覽，但兌換按鈕停用，需一般會員身份。

預覽依序檢查一般會員、格式、代碼存在、已領狀態、開始與結束時間；確認領取再檢查一次。時間含開始與結束端點；超過結束才算過期。商品由代碼決定，玩家不能自行選商品或改數量。

| 商品類別 | 成功後位置 | 不應連動 |
|---|---|---|
| 儲值銀幣 | 一般銀幣錢包、頂部與個人資訊同步 | 不增加付費儲值及 VIP 儲值指標 |
| 銅幣 | 一般銅幣錢包 | 不影響其他幣別 |
| 活動銀幣卡 | 新增未啟用卡，摘要／卡片總額增加，目前可用不因領取自動增加 | 不占每日任務節點，不立即入一般銀幣 |
| 活動金幣 | 活動金額增加，摘要與卡片概覽同步 | 不發卡、不開遊戲使用、不做流水或到期回收 |

每次成功新增一筆銀行獎勵紀錄，內容帶優惠碼、商品、幣別與數量。確認領取沒有等待期；先預覽或取消不消耗資格。同一登入來源＋帳號的同碼限一次；同步防止連點重複發放。發放未成功時不消耗該碼資格，仍留原因提示；刪除或合併已取得的卡不恢復資格。

| 情況 | 提示與返回 |
|---|---|
| 訪客／未登入 | 請先註冊或登入一般會員後再兌換 |
| 格式錯誤 | 請輸入 8 碼英文字母或數字 |
| 不存在 | 找不到此優惠碼，請確認後再試 |
| 已領取 | 您已兌換過此優惠碼 |
| 未開始／過期 | 此優惠碼尚未生效／已過期 |
| 無法發放 | 目前無法領取，請重新確認優惠碼或獎勵期限 |

預覽失敗留表單；確認階段失敗留確認層，可取消回表單。重新輸入會清除錯誤及前次成功區。可兌換期間以台北時間展示；活動銀商品顯示卡片使用期限，實際到期計算引用 [02.7](02-shared-rules.md#legacy-02-7)／07.4 的本地日界現況。一般銀／銅原型入帳後無使用期限；活動金明示使用及到期規則未定義。

| 測試碼 | 商品／結果 | 測試條件 |
|---|---|---|
| G6Y2A8U4 | 活動金 1,000 | 2026 年可兌換，會員未領 |
| K7M2X9P4 | 銀幣 2,000 | 同上 |
| B8R3N6T2 | 銅幣 3,000 | 同上 |

| E4Q8W2R6 | 過期錯誤 | 2020 年已結束 |
| F9D3J7L2 | 尚未生效 | 2099 年才開始 |

## 6. 狀態說明

代碼僅在已有原型列舉時對照，不鎖定正式後端 schema；各群組不可互相推導。

| 付款介面狀態 | 操作規則 |
|---|---|
| 確認 | 可選通路、確認或關閉 |
| 處理中 | 關閉停用，不先建處理中紀錄 |
| 成功 | 已入帳，按完成退出 |
| 入帳失敗 | 回確認並顯示原因 |

| 原型金融紀錄代碼 | 顯示 | 含義 |
|---|---|---|
| success | 成功 | 新完成 Mock 紀錄使用 |
| processing | 處理中 | 可能存在於歷史種子 |
| failed | 失敗 | 可能存在於歷史種子，沒有據此定義重試 |

| 優惠碼狀態 | 結果 |
|---|---|
| 可預覽 | 資格、格式與期限通過，尚未領取 |
| 確認成功 | 發至對應位置，資格已用 |
| 未開始／過期／不存在／已領 | 依原因阻擋，不發放 |
| 確認時失效 | 留確認層顯示原因，不消耗未成功資格 |

### 原型限制與例外

價格、促銷文字及測試碼皆屬本版展示配置。優惠碼已領狀態及活動金在同頁生命週期按身份保留，關閉銀行不重置；刷新重置。帳號分區使用登入來源加精確帳號字串，未統一帳號大小寫；優惠碼本身轉大寫的規則不等於帳號正規化。其他錢包、卡片及金融紀錄有不同生命週期，不能把優惠碼的身份區分推及整套帳務。

付款、儲值入帳與優惠碼領取是不同流程，不互相代替。補簽扣款、信箱附件等目前不是每筆都建立銀行紀錄；查紀錄時不得推論「沒紀錄就一定沒改餘額」。正式資料一致性或錯誤補償應以相關工作單另列結果。

## 7. 查詢、排序與分頁

紀錄初始顯示全部類別、全部狀態；類別與狀態同時生效，選取後立即更新，不需按查詢。**目前無日期篩選、分頁或紀錄詳情入口**，不能把個人資訊遊戲紀錄的日期查詢套用到此。

| 類別 | 收錄內容 |
|---|---|
| 全部 | 所有本機紀錄 |
| 儲值 | 儲值及既有提領種子紀錄；不代表本版另有提領操作入口 |
| 保險箱 | 存入、取出及既有保險箱相關種子紀錄 |
| 贈禮 | 玩家贈禮及既有禮包種子紀錄 |
| 兌換 | 金銀幣兌換 |
| 獎勵 | VIP、優惠碼、獎勵卡轉換及既有返水種子紀錄；不代表新增返水功能 |

狀態可選全部、成功、處理中、失敗；新完成的 Mock 操作直接新增成功紀錄，付款處理中不會先新增一筆處理中紀錄。歷史種子可包含其他狀態，不能推定都有對應重試流程。

列表保留資料順序，新操作加在最上方，並非依日期重新排序全部舊資料。每筆列來源／方式、日期、識別碼、金額與狀態。存入／贈禮以支出呈現，取出不加支出符號；兌換顯示來源 → 目標數量。無結果顯示「目前沒有符合條件的紀錄」。

## 8. 操作與跳轉

### 入口、預設畫面與返回

| 入口／操作 | 預設及帶入內容 | 關閉／完成結果 |
|---|---|---|
| 底部銀行 | 銀行中心預設儲值 | 主關閉回大廳 |
| 頂部 BUY／錢包 | 使用導航保留的銀行初始頁籤，最初為儲值 | 不是每次強制儲值；銀行內切頁不等於改導航初值 |
| 卡片轉換結果查看紀錄 | 結束遊戲，直接開銀行紀錄 | 初始篩選全部類別、全部狀態，不只限該卡 |
| 儲值方案／促銷立即購買 | 疊加 APP 商店儲值，帶入方案，初選 App Store | 確認前關閉不入帳；成功按完成回底層銀行或促銷 |
| 優惠頁輸入碼 → 兌換 | 成功後開確認優惠碼兌換 | 取消／關閉返回表單、保留輸入；沒有入帳或紀錄 |
| 優惠碼確認領取 | 再驗證並立即領取 | 成功關確認層、清空輸入、留優惠頁呈現結果；失敗留確認層顯示原因 |

銀行主視窗、付款及優惠碼確認不以背景點擊關閉。促銷輪播可以背景關閉；付款處理中關閉停用。銀行內切換頁籤時紀錄篩選保留，但優惠碼輸入、錯誤及成功區會隨該頁重新進入而初始化，領取資格仍保留。

### 帶入資料

| 操作 | 帶入資訊 |
|---|---|
| 開銀行 | 入口指定或導航保留的預設頁籤 |
| 購買／付款 | 選定方案、入帳金幣、售價、玩家識別及商店通路 |
| 優惠碼預覽／確認 | 輸入碼、當前身份、最新資格及商品期限；確認再檢核 |
| 紀錄篩選 | 類別與狀態，兩者同時生效 |
| 取消預覽／付款確認 | 無入帳資料；返回下層 |

### 操作流程

| 流程 | 玩家動作 | 系統結果與完成位置 |
|---|---|---|
| 儲值 | 選方案 → 核對 → 選通路 → 確認付款 → 完成 | 處理成功後加金幣及一筆紀錄，返回底層銀行／促銷 |
| 促銷 | SALE／促銷圖示 → 切換方案 → 立即購買 | 帶選中方案進同一付款流程；取消付款不關閉底層促銷 |
| 優惠碼 | 輸入 → 兌換預覽 → 確認領取 | 再檢核後即時發至對應位置；留優惠頁顯示領取成功及去向 |
| 查紀錄 | 銀行紀錄 → 選類別與狀態 | 即時篩選，共用紀錄不因切頁刪除；主關閉重開篩選重置 |

| AC-08-012 | US-08、US-13 | Given：已有儲值、VIP、優惠碼、卡片轉換與資產操作結果；When：查看新增紀錄順序及內容，再刷新；Then：新操作在頂部，來源、幣別及狀態正確；刷新回金融種子，不把種子當新交易。 |

## 14. 這個功能需要的資料

| 能力 | 輸入 | 輸出 | 規則 |
|---|---|---|---|
| 付款 | 方案、身份、通路 | 入帳金幣及單筆紀錄或失敗 | 不另加 BONUS、不改 VIP 儲值指標 |
| 優惠碼 | 碼、身份、最新資格與期限 | 商品去向、已領結果及紀錄 | 失敗不耗資格；活動金不發卡 |
| 金融紀錄 | 類別、狀態及共用紀錄 | 符合兩條件的列表 | 保留資料順序；沒有日期查詢或分頁 |

### 跨介面影響與保存

| 內容 | 所需資料與更新 |
|---|---|
| 方案／付款 | 名稱、金幣、售價、通路、操作身份與成功／失敗結果；成功同步一般金幣與單筆紀錄 |
| 優惠碼 | 商品、資格、領取狀態、可兌換／使用期限；確認後回傳獎勵位置與結果，失敗不消耗資格 |
| 金融紀錄 | 類別、來源、時間、識別、幣別／數量與狀態；跨頁操作共用同一列表 |
| 保存 | 取得及更新所屬資料；各自生命週期依 [02.7](02-shared-rules.md#legacy-02-7)，不新增跨裝置保證 |
